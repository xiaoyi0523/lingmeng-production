机器人推送（对外事件流） ​

把站内业务事件以 JSON 形式推给你自己的脚本或机器人中转服务，灵萌不会直接替你发到 QQ/钉钉。

把站内业务事件（笔记发布、外卖订单、抽奖开奖等）以 JSON 推送到你自己的服务器脚本或中转服务（Pull / HTTP 回调 / WebSocket）。灵萌不会直接替你发到 QQ/钉钉/微信群。

通知控制台 → 机器人推送对外事件流
  • 机器人推送模块已在「我的模块」中开通（feature_key: openstream）
  • HTTP 回调时接收地址须公网 HTTPS 可达
  • 已明确要订阅的事件类型与目标区域

建议顺序

  1. 1
    流配置通知控制台 → 机器人推送 → 流配置：启用、勾选事件白名单
  2. 2
    新建接入点机器人推送 → 接入点：选区域、取数方式、复制 API Key
  3. 3
    对接脚本机器人推送 → 接入指南：按文档验签、拉取或收回调
  4. 4
    排障推送概览看今日事件；回调日志看 HTTP 失败原因

与通知、官方机器人的本质区别

「机器人推送」不是「官方机器人」：前者对外 Webhook，后者对用户站内私信。名称相近，菜单都在通知相关区域，务必按受众区分。

机器人推送（本文）受众：你的服务器/脚本。形式：JSON 事件流。用途：同步到 QQ 机器人、钉钉、自建告警
通知与推送受众：站内用户。形式：通知中心、微信模板、Push、短信
官方机器人受众：站内用户。形式：消息 Tab 里的平台助手私信，可人工/AI 回复
群聊私信受众：用户之间。形式：私聊/群聊，非系统事件出口

后台菜单（通知控制台 → 机器人推送）

推送概览今日事件量、接入点健康、快速判断有没有写入
流配置按区域启用对外事件流、事件类型白名单、Payload 档位、接入点上限
接入点新建 Pull / HTTP 回调 / WebSocket 端点，管理 API Key、IP 白名单
回调日志HTTP 投递成功/失败、重试与错误摘要
接入指南后台内置对接说明、事件类型表、验签示例

流配置

  1. 1
    选区域编辑「平台默认（region_id=0）」或新增区域专属行
  2. 2
    启用关闭后该区域不写入事件，也不能新建接入点
  3. 3
    勾选事件「允许事件类型」未勾选的类型，接入点订阅了也收不到
  4. 4
    保存未单独配置的区域继承平台默认行
允许能力HTTP 回调 / 内容拉取（Pull）/ WebSocket
Payload 档位精简 / 标准 / 完整（影响 JSON 字段多少）

新建接入点

  1. 1
    基础信息名称、绑定区域、分类（笔记转发/外卖告警/混合等）
  2. 2
    取数方式Pull 定时拉取 / HTTP 回调推送 / WebSocket 长连
  3. 3
    订阅事件须在区域流配置白名单 ∩ 本接入点 event_types 内
  4. 4
    HTTP 回调填回调 URL、Secret（验签）；可选 IP 白名单
  5. 5
    保存 KeyAPI Key 保存后通常只显示一次，请立刻复制；丢失可在接入点轮换

常见事件类型（以流配置页为准）

  • 笔记：发布、更新等
  • 外卖：新订单、已接单、已取消、骑手已分配
  • 抽奖：开始、开奖、取消
  • 圈子：公告等
  • 完整列表见后台「接入指南」与流配置勾选面板

验证是否生效

  • 流配置已启用，目标事件类型已勾选
  • 接入点已启用，API Key 已保存到脚本
  • 触发真实业务（如发笔记、下外卖测试单）
  • 推送概览今日事件数增加；HTTP 模式在回调日志见 SUCCESS

常见问题

接入点收不到任何事件流配置是否启用；事件是否在区域白名单；接入点是否订阅且启用；Key 是否正确。
回调一直失败URL 是否 HTTPS 公网可达；Secret 验签是否一致；IP 白名单是否误拦；看回调日志错误摘要。
和通知控制台「通知记录」有什么关系通知记录是发给用户的渠道投递；机器人推送是发给外部系统的 JSON，两者数据源不同、菜单不同。
Key 丢了怎么办接入点执行轮换 Key，旧 Key 立即失效，脚本侧同步更新。
能直接推到 QQ 群吗不能。需自建脚本接收事件后调用 QQ/钉钉等第三方 API。
