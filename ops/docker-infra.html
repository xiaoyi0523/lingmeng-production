介绍如何通过 Docker 可选启动 Meilisearch（搜索）与 Gorse（推荐）等组件；不包含应用主程序、MySQL、Redis。

运维 · 可选基础设施·运维执行，管理员知晓Docker 栈
  • 服务器已安装 Docker 与 Docker Compose（或 docker compose 插件）
  • 灵萌应用已至少启动过一次，以便释放部署文件到服务器目录
  • 由运维执行命令；管理员只需知道「启用了什么」并在后台搜索索引中查看状态
管理员需要做什么无需在后台填写 Docker 参数

Meilisearch Master Key、Gorse API Key 须与服务器配置文件相同，由运维维护；管理员不要自行修改生产密钥。

  1. 1
    搜索索引打开 系统监控 → 搜索索引，确认 Meilisearch 状态为在线
  2. 2
    推荐评估若启用推荐，打开 系统监控 → 相关推荐评估 查看是否连通
  3. 3
    异常上报搜索功能异常时，将搜索索引页错误截图发给运维
运维部署步骤
  • 停止栈（运维执行）：在同一目录运行 bash down.sh
  • 同机部署多套站点时，修改 .env 中的端口与栈名称，避免冲突
cd static/deploy
cp .env.example .env   # 首次：编辑密钥与端口
bash up.sh             # 启动栈，等价于 docker compose up -d
包含与不包含

Docker Compose 不提供 MySQL、Redis 和灵萌应用本身，这些须单独安装或使用云服务。

Meilisearch 全文搜索默认端口 7700
Gorse 相关推荐默认端口 8087 / 8088
NebulaGraph 社交图（高级，可选）默认端口 9669
区域配置Docker 栈为全站级，无区域菜单
  • 启用后所有区域共享同一搜索 / 推荐集群
验证是否生效
  1. 1
    运维侧执行 up.sh 后 docker ps 确认容器运行
  2. 2
    管理员侧系统监控 → 搜索索引 显示已连接、文档数 > 0
  3. 3
    客户端搜索能命中新内容
常见问题
up.sh 找不到？先启动灵萌应用，部署文件会展开到运行目录下的 static/deploy/。
搜索索引仍离线？运维检查容器是否运行（docker ps）；Master Key 是否与 config.yaml 中 meilisearch 段一致。
可以不装 Meilisearch 吗？可以；小规模可用内置能力。用户量大或搜索延迟高时再启用 Docker 版。
Gorse 必须装吗？否；仅当需要个性化相关推荐时可选安装。
